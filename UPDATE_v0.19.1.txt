D&D Card Table v0.19.1 — Spell List Hotfix

ЧТО ИСПРАВЛЕНО

1. Ошибка «This spell is not on the Bard spell list» при добавлении
   доступного заклинания. Исправление распространяется на все восемь
   классов с поддерживаемой системой заклинаний.
2. Вместо [object Object] поисковые списки показывают имена классов.
3. Обычный выбор заклинаний, Magical Discoveries и выбор заговоров
   для Eldritch Invocations используют одинаковое распознавание классов.
4. Проверка добавления учитывает дополнительный заговор от выбранных
   Thaumaturge у Cleric и Magician у Druid.

ПРИЧИНА

Импортёр сохраняет classes как JSON. Там могут находиться объекты вида
{"name":"Bard","key":"srd-2024_bard"}, а не только строки "Bard".
Старый поиск находил класс в JSON, но при добавлении String(classes)
превращал объекты в [object Object] и ошибочно отклонял заклинание.
Теперь поиск, подписи и проверка используют общий список имён классов.
Название класса сравнивается целиком; упоминание в описании или данных
источника не даёт доступа к чужому списку.

УСТАНОВКА ПОВЕРХ v0.19

Это накопительное обновление файлов, а не самостоятельная установка.

1. В окне PowerShell с запущенным сервером нажмите Ctrl + C.
2. Распакуйте содержимое архива в существующую папку:
   C:\Users\Имир\Desktop\dnd-card-table
   Согласитесь на замену файлов.
   Проверьте, что рядом с src\web\server.mjs появился spell-classes.mjs.
3. Запустите:

   cd C:\Users\Имир\Desktop\dnd-card-table
   npm.cmd run web

4. В браузере нажмите Ctrl + F5.
5. В верхней панели и внизу страницы должна появиться версия 0.19.1.

Для перехода с v0.19 миграции, npm install и повторный импорт не нужны.
Этот патч не переписывает сохранённые записи персонажей и заклинаний.

КАК ПРОВЕРИТЬ

1. Откройте того же Bard → Spells.
   Найдите заклинание, на котором возникала ошибка.
   Ожидается: в результате поиска показаны названия классов,
   например Bard, Cleric, Wizard, вместо [object Object].

2. Выберите результат и нажмите Add spell.
   Ожидается: заклинание появляется на листе; ошибка про список Bard
   больше не возникает для доступного заклинания.
   Для этой проверки должно оставаться свободное место в лимите.

3. При свободном лимите добавьте один заговор (Cantrip) и одно
   заклинание Level 1 из доступных результатов.
   Ожидается: соответствующие счётчики увеличиваются; уже добавленные
   заклинания исчезают из списка вариантов для повторного добавления.

4. Обновите страницу и заново откройте персонажа.
   Ожидается: добавленные заклинания сохранены.

5. Если есть другой заклинатель, повторите добавление у него.
   Ожидается: тот же результат. Чужие списки и недоступные уровни
   не должны появляться в обычном выборе заклинаний.

Дополнительно для College of Lore уровня 6+:
Features → Magical Discoveries → поиск и добавление доступного
заклинания при свободном лимите. Подписи классов читаемые,
добавленное заклинание отмечается Always Prepared.

Сообщения Cantrip limit reached и Prepared spell limit reached означают,
что лимит действительно заполнен. Это отдельная проверка ограничения;
данный патч не снимает лимиты класса.

ЕСЛИ ОШИБКА ОСТАЛАСЬ

Пришлите название заклинания, класс и уровень персонажа, версию внизу
страницы, скриншот ошибки и текст ошибки из окна PowerShell.

ПРОВЕРКА РАЗРАБОТЧИКА

На исходной v0.19 воспроизведена точная ошибка добавления Bard.
На v0.19.1 прошли 29 тестов: форматы данных, восемь классов,
заговоры, подписи в поиске, ограничения уровня/количества,
Wizard Spellbook, дополнительные заговоры классовых выборов,
Magical Discoveries и цели Eldritch Invocations.
Синтаксис server.mjs и spell-classes.mjs проверен Node.js.
SQL в автоматических тестах имитируется; подключение к реальной
PostgreSQL и проверка в вашем браузере не выполнялись.

Для повторного запуска этих тестов из папки проекта:
   npm.cmd run test:spell-lists

СВЯЗАННЫЕ ОГРАНИЧЕНИЯ

Этот патч посвящён добавлению заклинаний. Известная проблема проверки
концентрации при уроне через Encounters остаётся отдельной задачей.
