# D&D Card Table v0.23.0 — русификация и перевод контента

Это обновление существующего проекта v0.22.1. Архив содержит изменённые файлы и необходимые модули, а не отдельную установку с базой данных.

## Установка

1. Остановите запущенный сервер.
2. Распакуйте содержимое архива в папку существующего проекта с заменой совпадающих файлов.
3. Откройте терминал в этой папке и выполните:

```powershell
npm.cmd install
npm.cmd run web
```

На Linux/macOS используйте `npm` вместо `npm.cmd`. Откройте сайт и обновите страницу через Ctrl+F5. Миграции и повторный импорт справочников для этого обновления не нужны.

## Что уже переведено

Переведены доступные в исходниках меню, формы, подсказки, сообщения об ошибках, справка, встроенные описания возможностей классов и динамические строки. Аудит извлечённых строк интерфейса: 1176 из 1176. Этот показатель относится к исходникам приложения, а не к содержимому вашей PostgreSQL.

Словарь терминов учитывает редакции 2014/2024 и тип записи. Канонические английские данные, идентификаторы, значения форм и формулы остаются основой игрового движка. Отображаемые подписи переводятся отдельно. Переключение RU/EN перезагружает страницу с выбранным языком.

## Что нужно для полного перевода вашей базы

В исходном архиве нет вашей PostgreSQL. Поэтому длинные описания импортированных заклинаний, существ, предметов и других записей не были доступны для перевода. Это обновление не выдаёт их отсутствие за завершённый перевод.

Внизу сайта откройте **«Перевод» → «Скачать тексты для перевода»**. Полученный `dnd-translation-input.json` прикрепите в чат, чтобы перевести именно ваш каталог. Выгрузка содержит тексты справочника и сведения об их источниках; персонажи, заметки игроков, изображения и настройки подключения не включаются.

Альтернативный способ — запустить `EXPORT_TRANSLATION.cmd` или выполнить:

```powershell
npm.cmd run i18n:export
```

Файл появится в корне проекта. Команда использует ваш существующий `.env` и не требует запущенного веб-сервера.

Страница «Перевод» отдельно считает готовые термины, сохранённые переводы, машинные переводы и оставшиеся английские тексты. Готовый пакет можно импортировать командой:

```powershell
npm.cmd run i18n:import -- --input путь-к-пакету-ru.json
```

После импорта обновите страницу. Пакет сохраняется в `data/translations/ru.json`; готовые переводы работают без модели и подключения к переводчику. Пустой `ru.json` намеренно не включён в обновление, чтобы распаковка не стёрла накопленный перевод.

## Автоматический перевод новых записей

Для автоматического перевода подключается локально установленная модель Ollama. Сервис и модель необходимо установить и запустить отдельно; в архиве нет модели. В существующий `.env` добавьте:

```dotenv
LOCALIZATION_MODEL=имя-вашей-установленной-модели
LOCALIZATION_URL=http://127.0.0.1:11434/api/chat
LOCALIZATION_AUTO=1
```

Замените значение `LOCALIZATION_MODEL` точным именем своей модели. Перезапустите сайт. Пока он работает, проверка каталога выполняется при запуске и затем раз в две минуты. Новые и изменённые тексты переводятся и сохраняются автоматически; неизменившиеся повторно не переводятся. Проверенные переводы не заменяются машинными.

Для одного запуска без фонового режима:

```powershell
npm.cmd run i18n:translate
```

Можно сначала обработать несколько новых текстов:

```powershell
npm.cmd run i18n:translate -- --limit 10
```

При ошибке сервиса успешно сохранённые пакеты остаются на месте; следующий запуск продолжает работу. По умолчанию разрешён только локальный адрес. Если вы самостоятельно выбираете удалённый совместимый сервис, требуется `LOCALIZATION_ALLOW_REMOTE=1`; необязательный `LOCALIZATION_API_KEY` хранится только на сервере.

Автоперевод использует словарь терминов и контекст редакции/источника. Числа, формулы, ссылки и служебные подстановки защищаются маркерами. Перед сохранением проверяются их сохранность, структура таблиц и списков, отсутствие явного сокращения и добавленного HTML. Эти проверки не доказывают правильность всех условий и исключений в механике: машинный результат всегда отмечается отдельно от проверенного.

Изменение исходного английского текста, редакции или источника создаёт новую запись перевода. Длинные тексты разбиваются по предложениям/строкам без обрезки. Пакет записывается атомарно после каждой порции, а параллельные изменения защищены блокировкой.

## Проверка и дальнейшие обновления

```powershell
npm.cmd test
npm.cmd run i18n:audit:ui
npm.cmd run i18n:audit
```

`i18n:audit:ui` проверяет извлечённые строки интерфейса и встроенные описания. `i18n:audit` проверяет фактические тексты импортированного каталога; код завершения 2 означает, что часть ещё не переведена. Новые строки интерфейса при разработке добавляются в словарь, а аудит показывает пропуски. Автоматический фоновый перевод обслуживает импортируемый каталог.

Проведено 88 автоматических тестов: выгрузка из тестовой PostgreSQL, разграничение редакций, обновление и возобновление перевода, защита формул и чисел, длинные описания, значения форм и существующие механики персонажей. Контракт Ollama проверен на тестовом ответе; реальная модель в этой среде не запускалась. В Chromium проверены страницы класса и выбора умений на тестовых данных, переключение RU/EN и мобильная ширина 390 px: ошибок JavaScript и горизонтального переполнения нет. Проверка вашей рабочей базы возможна после получения выгрузки.

## Файлы реализации

- `src/web/assets/ui-ru-extra.mjs` — дополнительные русские строки и шаблоны.
- `src/web/assets/i18n-core.mjs`, `i18n.js` — перевод интерфейса и переключение языка.
- `src/localization/` — сбор текстов, память перевода, проверка, провайдер и фоновый процесс.
- `scripts/localization/` — команды экспорта, импорта, перевода и аудита.
- `tests/translation-*.test.mjs` — проверки нового механизма.

Длинные переводы сторонних русскоязычных справочников массово не копировались: используется собственный перевод исходного текста и существующий словарь терминов проекта. Источники и лицензии исходных правил сохраняются.
