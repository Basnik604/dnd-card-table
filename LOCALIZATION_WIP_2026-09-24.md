# D&D Card Table — localization WIP audit

> Историческая запись до массового перевода. Перевод теперь собран: актуальный статус, проверки и ограничения приведены в `TRANSLATION_STATUS_RU.md`. Указанные ниже отсутствие `ru.json` и проблемы установки зависимостей относятся к прежнему состоянию.

Дата: 24 сентября 2026 года
База: чистый v0.23.0 localization engine.

## Что исправлено

- Добавлены `isTechnicalPath` и `isTechnicalSegment`.
- Из показателя покрытия исключаются только сегменты, у которых **все** места использования технические:
  `publisher`, `gamesystem`, `source_name`, `source_index`, `image`, `index`, `dexMode`, `feature_type`, `trait_type`, ветки `mechanics`, а также `traits.*.type`.
- `translationCoverage.total` теперь считает только отображаемые строки и отдельно возвращает `ignored`.
- `runTranslation` не отправляет технические сегменты провайдеру.
- Страница «Перевод» показывает число исключённых технических сегментов.
- `termTranslation` может переиспользовать встроенные UI-шаблоны, но только если результат выглядит как полный перевод, а не частичная подстановка.
- Частичные результаты вроде `Урон Resistance`, `Двумя руками Exploration`, замены только `gp/ft` и перевода только первого `Roll` в длинном правиле больше не считаются готовыми.
- `displayText` использует этот безопасный путь.
- Серверная HTML-локализация также использует безопасный `termTranslation`, поэтому длинный английский текст не должен становиться смешанным RU/EN из-за одного совпавшего шаблона.
- Контекстное правило для заклинания `Heal`: `Heal` → `Исцеление` при `kind=spell`; обычная UI-команда `Heal` остаётся «Лечить».
- Два regression-теста провайдера переведены на нейтральную строку `Custom rule 7d9.`, которой нет во встроенных UI-шаблонах.
- Добавлены отдельные тесты очистки каталога и jobs-регрессий.
- Добавлена команда `npm run i18n:audit:request`.

## Проверка тестов в текущем контейнере

Все тестовые файлы, не требующие отсутствующих внешних npm-пакетов, пройдены: **84 / 84**.

Полный `npm test` в этом изолированном контейнере не завершён только потому, что npm registry недоступен по DNS и нельзя доустановить `parse5` и `@electric-sql/pglite`. Два сценария, которые падали в прежнем WIP (`resume...` и `failed batch...`), отдельно воспроизведены в dependency-free regression tests и проходят.

Перед релизом всё равно требуется обычный `npm install` / `npm ci` в рабочем окружении и полный `npm test`.
