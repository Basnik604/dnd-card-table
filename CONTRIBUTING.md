# Разработка

GitHub — актуальный код, Linear — задачи. `main` поддерживаем рабочим. Изменения делаем в `feature/*` или `fix/*`, затем PR с проблемой, результатом, ограничениями и проверкой.

```sh
npm ci
npm test
npm run i18n:audit:ui
npx playwright install chromium
npm run test:tabletop:browser
```

Отдельный сценарий: `node tests/workspace.browser.mjs`. Браузерные тесты используют временную БД и настоящие обработчики стола; они не заменяют проверку установленной пользовательской базы.

Не коммитим `.env`, секреты, пользовательскую БД, `node_modules`, модельный кэш и временные результаты прогонов. Схема обновляется миграциями без удаления данных. Не изменяем уже применённые миграции ради новой функциональности.

## Защита main

CI-файл сам по себе **не включает защиту ветки**. В GitHub → Settings → Rules → Rulesets/Branch protection включите PR перед merge, запрет force push/удаления и обязательные проверки `unit-and-localization`, `tabletop-browser`. Проверки появятся после первого запуска workflow. Для одного разработчика не нужен обязательный внешний ревьюер.

Доступность зависит от тарифа и прав приватного репозитория. Пока правило не включено в GitHub, процесс PR соблюдаем вручную. Задача настройки — BAS-9.
