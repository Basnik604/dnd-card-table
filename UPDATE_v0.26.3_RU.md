# D&D Card Table v0.26.3 — Dedicated Live Roll API Hotfix

## Что исправлено

После пользовательской проверки v0.26.2 выяснилось, что интерактивные броски Channel Divinity всё ещё могли попадать в обычный HTML-маршрут `POST /character/:id/class-action`. Его нормальное поведение для формы — `303` и переход обратно на лист персонажа, поэтому попытки согласовать JSON через заголовок или скрытое поле оставались хрупкими.

В v0.26.3 для live-roll действий класса добавлен отдельный маршрут:

`POST /api/character/:id/class-action`

Он всегда отвечает JSON и не выполняет HTML-редирект. Клиент автоматически направляет только формы с `data-live-roll` и `/class-action` на этот API. Обычные формы персонажа продолжают использовать прежний маршрут и поведение.

Дополнительно:
- `/api/*` принудительно считается JSON-контекстом даже при ошибке;
- `fetch` использует `redirect: error`, поэтому неожиданный редирект больше не маскируется переходом на HTML;
- cache-busting для `table-ui.js`, CSS и i18n поднят до `v=0.26.3`;
- исправлен устаревший регрессионный тест v0.26.2, который всё ещё ожидал старую схему query-параметра.

## Установка

1. Остановить сервер (`Ctrl+C`).
2. Наложить архив v0.26.3 поверх текущей папки с заменой совпадающих файлов.
3. Не удалять `.env`, БД и старые базовые файлы.
4. Запустить `npm.cmd run web`.
5. Открыть страницу и нажать `Ctrl+F5`.
6. Внизу страницы проверить `v0.26.3`.
7. Проверить Divine Spark → «Бросить лечение».

Ожидается JSON-ответ с броском, отображение результата и немедленное уменьшение Channel Divinity на 1.

Новых зависимостей и SQL-миграций нет.
