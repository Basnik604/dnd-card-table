# D&D Card Table v0.26.2 — Live Roll Routing Hotfix

Дата: 25 сентября 2026 года.

## Что исправлено

После v0.26.1 диагностическое окно подтвердило вторую ветку ошибки: клиент уже требовал JSON, но добавление `?_response=json` к URL интерактивного действия на пользовательской установке приводило к HTTP 404.

В v0.26.2 JSON-режим больше не меняет URL маршрута. Клиент добавляет `_response=json` в тело POST-запроса. `parseForm()` на сервере поднимает этот флаг на объект запроса, поэтому обработчик и общий обработчик ошибок знают, что ответ должен быть JSON, даже если заголовок `Accept` был потерян или изменён окружением.

Сохранены обратные варианты определения JSON через `Accept` и query-параметр для совместимости, но новые live-roll запросы query-параметр больше не используют.

## Что не менялось

- Формулы и правила Channel Divinity.
- Расход ресурсов.
- PostgreSQL-схема и миграции.
- Пакет локализации каталога.
- Зависимости npm.

## Проверка

Выполнено:

```text
node --check src/web/server.mjs       — успешно
node --check src/web/assets/table-ui.js — успешно
node --test tests/live-roll-json.test.mjs — 3/3
```

Полный `npm test` в среде сборки не запускался до конца из-за отсутствующего локального пакета `typescript` в восстановленной `node_modules`; это ограничение среды, а не падение нового теста.

## Проверка пользователем

1. Остановить сервер.
2. Наложить архив v0.26.2 поверх текущей установки с заменой совпадающих файлов.
3. Запустить `npm.cmd run web`.
4. Нажать `Ctrl+F5`.
5. Проверить версию v0.26.2 внизу страницы.
6. Открыть жреца 2+ уровня.
7. Нажать «Бросить лечение» у «Божественной искры».
8. Ожидается: окно костей показывает результат, отсутствуют `<!DOCTYPE ...`, `HTTP 404` и сообщение об HTML-ответе; ресурс сразу уменьшается на 1.

Если до установки хотфикса действие уже было нажато и ресурс уменьшился, сначала восстановить его отдыхом/обычным способом либо создать тестового персонажа; не нажимать повторно только ради проверки старой ошибки.
