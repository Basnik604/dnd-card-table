D&D Card Table v0.20.1 — исправление сохранения Builder Data

Лог v0.20: скачаны 363 записи, все записи завершились с failed,
а итоговый счётчик ошибочно описывал скачанный каталог вместо базы.

Исправления:
- Запись совместима с обоими вариантами уникального ключа content_entities:
  (source_id, external_key) и (source_id, entity_type, external_key).
- Запись сущности, нормализация и теги выполняются одной транзакцией.
  При ошибке откатывается только текущая запись; импорт других продолжается.
- Повторный импорт сохраняет существующие ID и обновляет данные без дублей.
- В консоли показываются первые три конкретные ошибки каждой группы
  с названием записи и SQL-кодом. Полный список остаётся в import_runs.
- Итог Saved Builder Data totals читается из базы. Скачанные кандидаты
  подписаны отдельно. Неуспешный импорт возвращает ненулевой код завершения.
- Исправлен контраст поля Ruleset на странице Builder Data.

Установка поверх v0.20:
1. Остановить приложение (Ctrl+C).
2. Распаковать архив в корень проекта с заменой файлов.
3. В терминале из корня проекта выполнить:

   npm.cmd install
   npm.cmd run import:charactercontent
   npm.cmd test
   npm.cmd run test:import
   npm.cmd run web

Новых миграций нет. Нужны прежние миграции до 017 включительно.
Базу удалять или пересоздавать не нужно. Архив включает изменения v0.20.

Как проверить:
1. Импорт должен закончиться строкой:
   Character content import completed successfully.
   В группах должно быть failed: 0.
2. Saved Builder Data totals показывает сохранённые записи, ориентир:
   class 26, subclass 125, species 63, background 58, feat 91 (всего 363).
   Числа могут измениться при обновлении внешнего каталога.
3. После запуска нажать Ctrl+F5. Внизу страницы должна быть версия v0.20.1.
4. Builder Data -> All imported: количество должно соответствовать Saved
   Builder Data totals, а не оставаться 54. Поле Ruleset — тёмный текст
   на светлом фоне, без белой полосы с бледными буквами.
5. Guided Character Builder -> Expanded: ориентир 12 классов,
   114 подклассов, 56 видов и 29 предысторий после исключения несовместимых
   записей и объединения точных дублей. Создать персонажа с новым вариантом.
6. Повторить импорт: количество не должно удвоиться, существующие персонажи
   и ссылки на записи должны сохраниться.

Проверки разработчика:
- 41 обычный тест.
- 3 интеграционных теста на PostgreSQL-движке PGlite: оба уникальных ключа,
  создание пяти типов записей, повторная загрузка и сохранение ID,
  откат при ошибке, конкретные SQL-ошибки и итог по реально сохранённой базе.
- На схеме с тройным ключом воспроизведена ошибка старого запроса 42P10.
  В присланном логе оригинальная SQL-ошибка не выводилась, поэтому точный
  код ошибки пользовательской базы по этому логу установить нельзя.
- Проверки не подключались к вашей локальной базе.
- test:import требует Node.js 22.13+ (рекомендуется установленный Node 24).
