## Этапы 0.32

1. **0.32.0 — оболочка:** существующие локации и инспектор, нижняя зона подсказок, закрытие/возврат, режим карты, сохранение и сброс личной раскладки. Реализовано в открытом PR #1.
2. **0.32.1 — доки:** изменение размеров, перемещение панелей, вкладки, минимальные размеры и доступ с клавиатуры. Реализовано в PR #2 (BAS-7), поверх PR #1.
3. **0.32.2 — панели данных (BAS-8, PR #3):** инвентарь, заклинания, способности, библиотека существ, контекст выбранного токена. Карточка и панели используют одни записи и действия.
4. **0.32.3 — свободные окна (PR #4):** карта на весь экран, независимые окна, перемещение и изменение размера, компактные меню, масштаб содержимого каждого окна, разворачивание локации на фоне. Автоматические проверки прошли; пользователь подтвердил работу обновлённой локальной копии. Подробные результаты остальных ручных сценариев остаются в QA_v0.32.3_RU.md.

## Следующий этап: 0.33 Online

1. Вход и серверная идентификация пользователя. Локальный режим мастера остаётся доступным отдельно.
2. Приглашения в сессию и роли мастер/игрок. Сервер проверяет доступ до выдачи карты, токенов и листов персонажей.
3. Представление игрока и ограничения действий. Старые маршруты листа и библиотеки также требуют проверки: защита только стола недостаточна.
4. Синхронизация, конфликты и переподключение.

Каждый пункт выпускается отдельным проверяемым PR. Выход в интернет допускается после проверки всей поверхности доступа; сам по себе вход на страницу не означает готовность к публичному запуску.

## Принципы

- Game State (персонажи, сцены, токены, бой) хранится и проверяется сервером.
- Workspace State содержит только личные настройки отображения. В 0.32.0 — версионированный localStorage для сессии и локального мастера. Отдельные учётные записи появятся с Online.
- Изменение панелей не меняет размер клетки и координаты токенов. Черновики скрытых форм остаются на странице.
- Инвентарь, ресурсы и заклинания не дублируются; существующие функции и представления выделяются постепенно.
- Обновления схемы идут миграциями без пересоздания пользовательской БД.
- Для Online сервер проверяет права до выдачи данных: скрытая в интерфейсе уже переданная мастерская информация не считается защищённой.
- Текущие API локального мастера не являются многопользовательской защитой.
