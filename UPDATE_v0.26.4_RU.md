# D&D Card Table v0.26.4 — исправление адреса интерактивных бросков

## Причина HTTP 404

Формы Channel Divinity содержат скрытое поле `name="action"`. В браузере оно перекрывает свойство `HTMLFormElement.action`. Старый клиент выполнял `new URL(form.action, location.href)` и отправлял запрос на `/character/[object%20HTMLInputElement]` вместо маршрута действия. Добавление JSON-заголовков и отдельного API в v0.26.1–v0.26.3 эту строку не исправляло.

Клиент теперь читает настоящий атрибут через `form.getAttribute('action')` с разрешением относительно `document.baseURI`. Поле `action=channel_divinity` сохраняется в POST-теле, а запрос попадает в существующий `/api/character/:id/class-action`. Версия и адреса статических ресурсов обновлены до 0.26.4.

Предыдущее объяснение, что ресурс обязательно успел списаться из-за редиректа, не было подтверждено. В воспроизведённом сценарии запрос не достигает обработчика действия; поэтому этот ошибочный запрос ресурс не расходует. Для конкретной установки фактическое значение можно проверить обновлением страницы.

## Установка на существующий проект

1. Остановить сервер через Ctrl+C и сохранить резервную копию рабочей папки.
2. Скопировать содержимое ZIP поверх рабочей папки с заменой совпадающих файлов. Не удалять базовые файлы, отсутствующие в ZIP: это накопительное обновление, не полный установочный комплект.
3. Сохранить существующие `.env` и PostgreSQL-базу. Новых миграций и обязательных зависимостей нет.
4. Запустить `npm.cmd run web`.
5. Нажать Ctrl+F5 и проверить внизу страницы `v0.26.4`.
6. У жреца с доступным ресурсом нажать «Некротический урон» у «Божественной искры». Должен появиться результат, а счётчик уменьшиться на одно использование.

- В браузерных проверках использованы реальные локализованные формы жреца из рендерера проекта и настоящий table-ui.js. HTTP-ответы подставляются тестом: проверяются адрес, POST-тело, вывод результата, изменение 2/2 → 1/2 → 0/2 и блокировка исчерпанного ресурса. Эти проверки не подключаются к пользовательской PostgreSQL-базе.

Дополнительная браузерная проверка: `tests/live-roll.browser.mjs`. Она запускается отдельно с Playwright и Chromium; инструкции указаны в начале файла. Для работы приложения они не нужны.
