# Сохранность данных v0.36

Карты, загруженные изображения токенов, портреты, персонажи, предметы, сцены и бой хранятся в PostgreSQL. Каталог `data` содержит файловые пакеты токенов, переводы и дополнительные данные. Полная копия v0.36 включает **всю базу** и **весь каталог data**. Это папка с `database.dump`, файлами и `manifest.json`; её можно перенести на другой диск.

Копии исходников в `codex-backups` не являются копиями кампании. `.env` с паролями и настройки localStorage в браузере в архив не входят. Сохраните `.env` отдельно в защищённом месте; личную раскладку можно восстановить или сбросить в интерфейсе. Кэш `.localization` и скачанные модели регенерируются и не включаются.

## Создать копию

1. Остановите web-сервер через Ctrl+C, импортёры и любые процессы записи. PostgreSQL оставьте работающей.
2. Для стандартной локальной установки Docker Desktop дождитесь Engine running.
3. Из рабочей папки проекта:

```powershell
npm.cmd run db:backup -- --docker --app-stopped
```

Команда напечатает путь `backups/backup-...`. При ошибке папка считается неполной, даже если `database.dump` уже появился. Полный манифест записывается последним. Не удаляйте предыдущие рабочие копии.

При установленных `pg_dump`, `pg_restore` и `psql` можно убрать `--docker`. Переменная `PG_BIN` задаёт каталог клиентских программ. Режим Compose поддерживает стандартный локальный PostgreSQL на порту 5432; нестандартный порт/удалённый сервер требуют нативных клиентов. Клиент должен поддерживать версию сервера.

```powershell
npm.cmd run db:backup:verify -- --backup="C:/путь/к/backup-..."
```

Проверка сверяет размер и SHA-256 каждого файла, обнаруживает отсутствующие и лишние файлы. Проверка чтения архива и полноты БД выполняется восстановлением, описанным ниже. Инструмент сравнивает содержимое таблиц и состояния последовательностей, а не только завершение процесса.

Не помещайте копии в Git: `backups/`, `*.dump` и `codex-backups/` исключены из репозитория. Копия содержит всю информацию кампании. Восстанавливайте только собственные доверенные копии: дамп содержит SQL-объекты.

## Проверить восстановление без замены рабочей базы

Создайте отдельную пустую базу. Пример использует стандартные локальные реквизиты из `.env.example`, **не меняет DATABASE_URL** и не удаляет исходную базу:

```powershell
docker compose exec -T postgres createdb -U dnd dndcards_restore_check
$env:RESTORE_DATABASE_URL = 'postgres://dnd:dnd@localhost:5432/dndcards_restore_check'
npm.cmd run db:restore -- --docker --app-stopped --backup="C:/путь/к/backup-..." --files-to="C:/путь/к/новой-папке-восстановления"
```

Каталог `--files-to` должен быть новым, а целевая база — пустой. Существующие базы и файлы не перезаписываются. При ошибке восстановления рабочая база остаётся прежней; отдельные тестовые результаты не подключайте к приложению.

Восстановление PostgreSQL выполняется одной транзакцией с остановкой при ошибке. После него проверяются все таблицы и последовательности, а внешние файлы сверяются с SHA-256. Успех обозначается `verified: true`.

После успешной проверки можно **отдельно** переключить копию приложения на восстановленную БД через её `.env` и использовать восстановленный `data`. Автоматического переключения и удаления старой БД нет. Перед подключением более новой версии приложения выполните её миграции.

## Обновить существующую 0.31.2 или 0.35.5

Сначала сохраните старую папку приложения, `.env` и `data`; обновляйте код без удаления базы и Docker volume. Установите зависимости через `npm.cmd ci` и сделайте копию приведённой выше командой. Импорт контента заново не нужен.

В старых версиях не было журнала миграций. Один раз зарегистрируйте уже установленную версию, передав **свежую проверенную копию именно этой БД**:

```powershell
npm.cmd run db:adopt -- --from=0.35.5 --docker --app-stopped --backup="C:/путь/к/backup-..."
```

Если исходная версия — 0.31.2, используйте `--from=0.31.2`. Проверяются ключевые признаки схемы; при несовпадении команда отказывается менять журнал. Другие исходные версии требуют отдельного разбора, а не подбора номера.

```powershell
npm.cmd run db:plan
npm.cmd run db:migrate -- --docker --app-stopped --backup="C:/путь/к/backup-..."
npm.cmd run web
```

Команда adopt записывает только историю; исторические исправления HP/XP/предметов заново не выполняются. `db:migrate` применяет только новые файлы, каждый в отдельной транзакции. Повторный запуск не меняет игровые данные. Изменённая применённая миграция и неизвестная более новая миграция вызывают отказ.

Индивидуальные старые команды `db:migrate:005` и аналогичные больше не выполняют SQL повторно. Для чистой пустой базы достаточно `npm.cmd run db:migrate` без adopt и без копии ещё не существующих данных.

Если используется нестандартный `LOCALIZATION_PACK` вне каталога `data`, сохраните его отдельно вместе с настройкой: стандартная копия охватывает только `data` и PostgreSQL.

## Основа реализации

Применяются штатные [pg_dump PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgdump.html) и [pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html). Бинарный поток передаётся напрямую, без текстового перенаправления PowerShell. Дамп содержит изображения BYTEA; резервная копия не зависит от повторной загрузки этих изображений из интернета.
