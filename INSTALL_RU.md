Для перехода достаточно порядка из `UPDATE_v0.26.0_RU.md`: остановить сервер, скопировать обновление и запустить снова. Новых зависимостей и миграций в v0.26.0 нет.

Для чистой установки сначала нужен исходный базовый проект и настроенная PostgreSQL. Эта инструкция описывает обновление уже работающего приложения.

## 1. Остановите приложение

В терминале, где запущен сайт, нажмите `Ctrl+C`. Если Windows спросит о завершении пакетного файла, подтвердите. PostgreSQL оставьте запущенной.

## 2. Сделайте рабочую копию

Скопируйте целиком папку работающего проекта в соседнюю новую папку. Например:

- старая папка: `C:\DnD\dnd-card-table`;
- новая копия: `C:\DnD\dnd-card-table-ru`.

Все дальнейшие действия выполняются в новой копии. Старая папка останется для возврата к прежнему коду.

В копию должны попасть ваш `.env`, базовые исходники и прежние служебные файлы. Копирование папки не создаёт резервную копию базы PostgreSQL: база хранится отдельно. Сохраните её резервную копию своим обычным способом, если она ещё не сделана. Новая папка с прежним `DATABASE_URL` будет использовать ту же базу, включая персонажей, карточки и заметки.

Если вы вручную редактировали `data/translations/ru.json`, сначала прочитайте раздел о сохранении собственных переводов ниже.

## 3. Распакуйте обновление

Распакуйте архив в отдельную временную папку, например `C:\DnD\update-ru`. Откройте её: рядом должны находиться `package.json`, `package-lock.json`, папки `src`, `data`, `scripts` и `tests`.

Скопируйте всё содержимое этой папки в `C:\DnD\dnd-card-table-ru`. Разрешите замену совпадающих файлов и объединение папок. Старые файлы, которых нет в архиве обновления, должны остаться на месте.

Проверьте три пути в новой рабочей папке:

| Файл | Что проверять |
|---|---|
| `package.json` | Находится непосредственно в корне папки, из которой будете запускать команды |
| `.env` | Ваш прежний файл настроек; имя не должно превратиться в `.env.txt` |
| `data\translations\ru.json` | Готовый файл перевода из обновления |

`.env` в архив не включён. Сохраните прежний `DATABASE_URL`: он указывает на вашу существующую базу. Для использования готового перевода настройки Google Translate, API-ключи и Ollama не требуются.

Если ранее включали фоновый перевод через `LOCALIZATION_AUTO=1`, для работы только с готовым пакетом измените эту существующую строку на `LOCALIZATION_AUTO=0`.

## 4. Откройте терминал в новой папке

Откройте новую папку в Проводнике, щёлкните по адресной строке, введите `powershell` и нажмите Enter. Либо перейдите в неё из уже открытого PowerShell:

```powershell
cd "C:\DnD\dnd-card-table-ru"
```

Путь выше — пример: замените его своим. Команды должны выполняться в папке, где находится `package.json`.

Можно проверить доступность уже установленного Node.js и npm:

```powershell
node --version
npm.cmd --version
```

Использование `npm.cmd` помогает обойти выбор PowerShell-файла `npm.ps1` без изменения политики выполнения скриптов Windows.

## 5. Установите зависимости

```powershell
npm.cmd ci
```

Дождитесь завершения и возврата строки ввода. Команда устанавливает версии зависимостей из `package-lock.json` и пересоздаёт папку `node_modules`. В обычном случае на этом этапе нужен доступ к npm registry. База и `.env` этой командой не пересоздаются.

Если вы обновляете уже работающую v0.25.0 (или v0.24.0) и папка `node_modules` осталась на месте, этот шаг можно пропустить: зависимости в v0.26.0 не менялись.

## 6. Проверьте перевод и подключение к своему каталогу

Сначала проверьте сам поставляемый пакет без подключения к базе:

```powershell
npm.cmd run i18n:audit -- --input data/translations/manifest.json
```

Ожидаемый результат включает:

```json
{
  "entities": 2008,
  "total": 8125,
  "ignored": 705,
  "reviewed": 0,
  "machine": 7276,
  "terms": 849,
  "pending": 0,
  "complete": true
}
```

Затем проверьте именно вашу PostgreSQL:

```powershell
npm.cmd run i18n:audit
```

Команда читает настройки подключения из `.env`; запущенный веб-сервер для неё не нужен. При совпадении базы со снимком ожидаются `pending: 0` и `complete: true`. Новые или изменённые английские записи могут дать другое число. Код завершения 2 этой команды означает неполное покрытие перевода, а не удаление или повреждение базы.

Для проверки кода можно выполнить:

```powershell
npm.cmd test
```

Для v0.26.0 добавлено 9 новых тестов Channel Divinity; они прошли 9/9. В восстановленном сборочном окружении также прошли 123/123 тестов, которые смогли загрузиться. Полный набор рекомендуется прогнать на вашей рабочей установке после `npm.cmd ci`; детали ограничения текущего окружения описаны в `UPDATE_v0.26.0_RU.md`.

## 7. Запустите сайт

```powershell
npm.cmd run web
```

Оставьте этот терминал открытым. По умолчанию приложение выводит:

```text
D&D Card Table Library running at http://localhost:3000
Health check: http://localhost:3000/health
```

Откройте адрес, который напечатан в терминале. По умолчанию это [http://localhost:3000](http://localhost:3000). Если в `.env` указан `WEB_PORT`, будет использован этот порт.

Для отдельной проверки соединения с базой откройте [http://localhost:3000/health](http://localhost:3000/health), подставив свой порт при необходимости. При успехе ответ содержит `"ok": true` и `"database": "connected"`.

## 8. Включите русский язык и проверьте результат

В верхней панели выберите `RU`, затем обновите страницу через `Ctrl+F5`. Откройте несколько заклинаний, предметов и классов. Проверьте свои сохранённые персонажи. Переключите язык на `EN` и обратно: английский режим должен показывать исходный текст.

После распаковки перевод уже лежит в `data/translations/ru.json` и загружается приложением автоматически. Отдельный импорт переводов требуется только для объединения с вашим существующим пакетом или для нестандартного расположения файла. Повторный импорт справочников и отдельные SQL-миграции для установки этого перевода не нужны.

После общей проверки выполните сценарий из `UPDATE_v0.26.0_RU.md` для жреца и паладина: проверьте расход Божественного канала, Divine Spark/Turn Undead, Divine Sense и доступные подклассовые варианты. Затем коротко перепроверьте Wild Shape из v0.25.0 и возможности колдуна из v0.24.0.

## Если уже есть собственный перевод

Этот порядок сохраняет ранее проверенные записи со статусом `reviewed`:

1. До распаковки сохраните старый `data/translations/ru.json` отдельно, например как `ru-before-update.json` вне папки обновления.
2. После объединения папок верните этот старый файл на место `data/translations/ru.json` в новой рабочей копии.
3. После `npm.cmd ci`, пока веб-сервер остановлен, импортируйте новый пакет из временной распакованной папки:

```powershell
npm.cmd run i18n:import -- --input "C:\DnD\update-ru\data\translations\ru.json"
```

Замените путь своим. Команда добавляет новые записи и не заменяет старую `reviewed`-запись новой `machine`-записью с тем же идентификатором. Ручные изменения, которые всё ещё помечены как `machine`, специальной защиты от замены не имеют; их сохранённая копия остаётся у вас.

## Частые проблемы

| Сообщение или симптом | Что проверить |
|---|---|
| Не найден `package.json` | Терминал открыт не в корне рабочей папки |
| `npm.ps1 cannot be loaded` | Используйте `npm.cmd` в командах этой инструкции |
| `node` или `npm.cmd` не распознаны | Проверьте установку Node.js и откройте новый терминал |
| `DATABASE_URL is missing` | В корне рабочей папки должен быть прежний `.env` с этой переменной |
| `ECONNREFUSED` при обращении к базе | Запущена ли PostgreSQL и сохранены ли правильные адрес и порт подключения |
| `password authentication failed` | Настройки `.env` должны совпадать с вашей работающей конфигурацией |
| `EADDRINUSE` | На этом порту уже работает сервер; остановите старое окно приложения |
| Ошибка `npm ci` о несовпадении lock-файла | `package.json` и `package-lock.json` должны быть скопированы из одного архива |
| Сайт по-прежнему английский | Выберите RU, обновите через Ctrl+F5 и запустите аудит текущей базы |
| Аудит снимка успешен, а аудит базы показывает пропуски | Состав базы отличается от приложенного снимка; нужен перевод добавленных или изменённых строк |

Если вы ранее задавали `LOCALIZATION_PACK`, убедитесь, что эта настройка не направляет команды или сервер на старый файл перевода.

## Возврат к прежнему коду

Остановите новое приложение через `Ctrl+C`, откройте терминал в сохранённой старой папке и запустите прежним способом. Это возвращает старые файлы приложения. Обе папки при прежнем `DATABASE_URL` используют одну базу: действия в приложении, меняющие данные, не отменяются сменой папки.

Пакет содержит машинный перевод с ограниченной постредактурой. Инструкция и проверки не означают, что ваша рабочая база уже проверена удалённо. Сведения о покрытии и замеченных дефектах исходника находятся в `TRANSLATION_STATUS_RU.md`.
