# v0.30.1 — смена размера клетки и восстановление каталога

Накопительное обновление для существующей установки v0.28–v0.30. Включает игровой стол из v0.29 и токены из v0.30. Новых npm-зависимостей нет.

## Токены после изменения сетки

В v0.30 размер клетки сразу менялся на экране, но действия с токенами блокировались до отдельного сохранения локации. Если последним сохранённым размером было 150 px, возвращение к нему снимало блокировку. На стенде воспроизведён этот сценарий; ограничения расчётов только размером 150 px не обнаружено.

Теперь перед добавлением, перемещением, редактированием или сменой портрета токена приложение сначала сохраняет изменённые настройки локации. Перетаскивание и привязка используют новую сетку. Над картой появляется пояснение, пока есть несохранённые настройки. Кнопка «Сохранить локацию» также остаётся доступной.

- При отказе сохранения сетки действие с токеном не выполняется. Можно исправить настройки или повторить действие.
- При конфликте с другой вкладкой показывается ошибка и кнопка обновления страницы.
- После увеличения клетки сервер может сдвинуть токен внутрь границ карты; последующее действие использует обновлённую версию токена.
- Рамка маленького токена уменьшается вместе с ним, чтобы не растягивать его относительно клетки.

Сетка и действие сохраняются последовательно. Если сетка уже сохранена, а следующий запрос токена завершился ошибкой, новая сетка остаётся сохранённой. При обрыве связи после отправки запроса сервер мог успеть записать изменение — обновление страницы покажет актуальное состояние.

## Установка

1. Остановите сервер через `Ctrl+C`.
2. Скопируйте содержимое ZIP в прежнюю папку проекта с объединением папок и заменой файлов. Сохраните `.env` и базовые файлы, которых нет в архиве. Это обновление, а не установка в пустую папку.
3. Запустите в этой папке:

```powershell
npm.cmd run web
```

4. Обновите сайт через `Ctrl+F5`. Внизу страницы должна быть версия **0.30.1**.

Для исправления токенов отдельные команды работы с базой и повторный импорт не нужны.

## Если появляется `relation "character_content" does not exist`

Эта таблица хранит данные справочника классов, подклассов, видов, предысторий и черт. Сообщение означает, что приложение не видит её в подключённой базе. Сам скриншот не позволяет различить пропущенную миграцию, другую базу в `.env` и изменение схемы подключения.

Вместо общей страницы с SQL-ошибкой теперь выводится инструкция. После установки обновления остановите сервер и выполните:

```powershell
npm.cmd run db:repair:character-content
```

Это **проверка без изменений**. Она показывает имя базы, наличие таблицы и число записей, которые можно восстановить. Если это ваша прежняя база и проверка разрешает восстановление:

```powershell
npm.cmd run db:repair:character-content -- --apply
npm.cmd run web
```

Команда создаёт недостающую таблицу и восстанавливает отсутствующие строки из `content_entities.raw_source`, используя тот же нормализатор, что и импорт Open5e. Интернет для восстановления не нужен. Уже существующие строки справочника, их ручные изменения, исходные записи и идентификаторы сохраняются; персонажи, карты, токены и сессии не изменяются. Восстановление выполняется в одной транзакции; при ошибке его записи отменяются.

Если исходников нет, таблица скрыта в другой схеме или структура отличается от ожидаемой, команда останавливается с объяснением. В этом случае сначала проверьте прежний `.env` и резервную копию базы. Создание пустой таблицы не восстановит потерянный справочник. Не публикуйте `DATABASE_URL` с паролем.

Файл `020_character_content_recovery.sql` использует команда восстановления. Для исправления сетки вручную запускать его не требуется.

## Как проверить

1. Откройте локацию с токеном. Поменяйте размер клетки со 150 на 70 px, не нажимая «Сохранить локацию».
2. Перетащите токен или выделите его и нажмите стрелку. Настройки сохранятся перед перемещением; токен займёт клетку нового размера.
3. Повторите с 50 или 100 px и обновите страницу: размер и положение должны сохраниться.
4. Проверьте добавление токена после очередного изменения размера и работу без привязки к сетке.

## Проверки выпуска

- `npm test`: 212 тестов, включая воспроизведение отсутствующей таблицы, восстановление и повторный запуск, сохранение существующих записей, отказ для пустой/другой схемы и откат при ошибке.
- Браузер: 36 пройденных сценариев. Размеры 5, 25, 37,5, 50, 70, 100, 149, 150, 151, 200 и 500 px; переход без отдельного сохранения; отказ сети, неверные значения, добавление и перезагрузка, граница карты и конфликт вкладок.
- Повторные браузерные проверки карты и токенов: перетаскивание, масштаб, изображения, портреты, мобильная ширина и сохранение.
- Аудит интерфейса: 1622 строки, непереведённых — 0.

Проверки использовали Chromium и изолированную PostgreSQL-совместимую PGlite. Доступа к вашей установленной базе нет; результат её восстановления определяется локальной проверкой.
